# PDF source integrity and page evidence

PDF ingestion now associates parser results with the individual input File, preserving distinct same-name sources and repeated text. Server-created references contain a SHA-256 of original bytes. Empty MIME PDFs become `application/pdf` after type detection, PDF signature checks and successful parsing. Explicit conflicting PDF extensions/MIME are rejected. Binary limits remain 8 MB; no dependencies or schema were added.

`pdf-pages-v1` retains the actual parser page count, every physical page (1-based), page text, and bounded raw text positions/ruling lines. Coordinates use **pdf2json page units**, as documented by the installed parser, not pixels, rendered bounding boxes or inferred financial rows. Printed page labels are not extracted or substituted for physical numbers. Canonical extracted text is not truncated; repeated chunks/pages are retained. Chunks and M1 extracted evidence identify physical pages. Empty pages mean no extracted text, not proven blank. Text-bearing pages also have unknown visual coverage. PDF coverage is never promoted to `full`, including restored legacy references; legacy inventories remain unknown until reattachment or source renewal.

## Using visual evidence

Upload a PDF and ask a content question, or refer to a selected saved PDF and physical pages, for example “read scanned page 2” or “extract transactions from pages 2-4.” Native inspection uses the existing `gemini-2.5-flash` through the installed `@google/genai`. A configured conversational provider synthesizes the structured findings; it does not need to support raw PDFs. This adds no universal OpenAI/native-provider promise. Google upload failure does not discard successfully parsed scanned PDFs: their original can be retained and the Gemini evidence path uses bounded inline PDF bytes.

For selected PDF content work, the path conservatively requests visual evidence even when text exists: pdf2json cannot establish that images or charts are absent. Locating a saved file and unrelated chat do not initiate this path. Same-name saved sources require an exact source selection or clarification. Saved PDF content questions resolve original attachment identities instead of treating arbitrary search snippets as coverage of a newly requested page.

A report must contain exactly the requested physical pages and the matching fingerprint. Strict JSON validation rejects unexpected provenance/coordinate fields, invented/duplicate/unrequested pages, invalid values, incomplete JSON and non-STOP/truncated/blocked responses. Readable and uncertain observations remain separate. Literal cell values are strings, with null for unclear digits/associations. No row arithmetic, column totals, reconciliation, inferred row mappings or mathematical verification is performed. Page-number validation checks provenance, not visual accuracy. File content and model observations are untrusted data, not user-stated facts or instructions.

Accepted raw model reports and page findings are retained in private, immutable per-page receipts beside the original source attachment, using flat names compatible with existing conversation cleanup. Each receipt binds actor, source chat, saved attachment, byte fingerprint, extraction version, provider and model. Concurrent writes for different pages do not overwrite completed pages. Reads hash the retained original and validate live current/source chat ownership; source changes invalidate reuse, and source-chat deletion makes late receipts inaccessible. A later request for cached pages performs no provider upload or inference. It still reads private source bytes to check integrity. Original unavailability and evidence unavailability are distinct errors.

The same source-labeled attachment evidence reaches generation and both required-review constructions through `createParams`. Independent assessment chooses its task separately from the candidate. No raw provider PDF reference is forwarded for a second inspection after the evidence attempt. Existing video routing, measured timelines, auth and required-review modes are preserved.

## Bounds and continuation

- At most four new physical pages per selected PDF per turn, one Gemini analysis request per PDF, 45-second API timeout, 6,000 output tokens and 60,000 response characters. SDK `httpOptions.retryOptions.attempts` is explicitly 1, including the original request. There is no inference retry after failure or ambiguous acceptance.
- The complete PDF is sent to Gemini, even for selected pages. There is **no physical page/token isolation**. Bounds constrain requested findings and output, not provider processing of the full file.
- At most 128 inspected pages can be cached per source. Larger work requires smaller source PDFs. Page receipts retain original raw reports; no OCR, browser PDF viewer, rendering service or generalized accounting engine is added.
- A request for every transaction remains explicitly partial when requested pages remain. “Continue” selects the next unfinished pages; generation receives those new pages instead of earlier irrelevant cached findings. Explicit page comparisons select findings from the entire requested page set, including cached and newly inspected pages. Prompt evidence reports omittedCachedPages when cached requested findings exceed the four-page context limit. Explicit integer page numbers, lists and ranges are supported. Cached readable or uncertain pages are reused; automatic reinspection of the same cached page is not provided.
- Canonical layout keeps up to 10,000 runs and 4,000 lines per page, with document-wide budgets of 50,000 runs and 20,000 lines and an explicit truncation flag. Inventories exceeding 10,000 physical pages are rejected with the parser-reported count. All extracted text and empty page records remain. Parser failure/30-second timeout rejects ingestion; it cannot masquerade as a successful blank scan. The timeout is an asynchronous guard, not process-level termination of synchronous parser work.
- Prompt context includes at most 200 inventory statuses, four layout samples (80 runs/40 lines, run text capped to 1,000 characters), four page observations and the existing bounded text chunk window. Original metadata/text/raw reports remain private and intact. Inventoried PDFs skip the older unbounded chunk-by-chunk model prepass.
- M1 indexes physical-page text and model findings with source/fingerprint/version and partial coverage. Index failures/incomplete batches are visible and recover by reopening the selected source without another inference for cached pages. Original-extraction indexing retains its existing durable retry mechanism; visual receipt indexing requires a revisit, with no new background job. Its canonical payload sorts saved pages and raw reports and excludes request-specific contextPages, state and notice, so different follow-up questions resume the same ingestion hash when the saved evidence is unchanged.
