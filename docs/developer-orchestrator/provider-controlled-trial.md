# Provider-controlled tic-tac-toe trial

This release candidate uses the existing version-1 Developer Orchestrator with
one owner-started, isolated game project. It introduces no product implementation.
Open a fresh owner-bound chat and select **Start the two-hour tic-tac-toe
trial**. The control calls Katie's existing game intake for `mfackrell/katie`
without a paid chat classifier, binds the fixed game brief to authenticated
owner consent, and sets the cutoff once.
After review, the existing project approval card binds the exact coding scope
to the authenticated owner. It permits an isolated draft and protected Preview.

One coding milestone targets `/milestone-3-tic-tac-toe`. Writes stay under the
dedicated directories of that name in `app/`, `lib/`, and `tests/`. Katie's
Director and functional leads choose their own organization and SMART
assignments. The application stays on its draft branch. Close only after
independent assessment, accepted components, and same-commit Preview evidence.

The trial uses Katie's existing configured OpenAI connection for bounded
mission requests and the existing isolated GitHub native host for coding and
independent review. Technical output, context, call counts, deadlines, retry
and execution scope checks still apply. The durable runner claim rejects
replay. Provider refusal or uncertain transport ends further trial execution.
Usage receipts are observations. The mode does not require a price record,
spending proposal, ledger reservation, or financial reconciliation. It does
not issue, increase, or switch credentials. Existing projects continue to use
their current paths and financial records.

Release requires separately authorized production migration and deployment.
Apply the new migration through the existing authoritative migration process
before relying on the new API or starting the trial. Verify the deployed
commit matches main, then use the owner start control. Record project and
workflow IDs, protected Preview, draft PR, exact SHA, independent browser
results, observed usage, and any repairs. An interrupted or ambiguous native
run preserves its checkpoint and one-shot claim for operator inspection.
