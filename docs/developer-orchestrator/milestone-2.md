# Milestone 2: Functional Director execution ownership

This slice connects the deployed hierarchy to the existing `mfackrell/katie` cumulative coding workflow. It does not add a repository adapter, execute a live project, or establish live inference autonomy.

## Behavior

A Functional Director or subordinate manager commissions a package for an approved milestone. Its durable contract contains the objective, deliverables, interfaces, acceptance criteria, earlier-package dependencies, scoped paths, token and monetary caps, deadline, attempt limit, and three appointed execution identities (coding, technical composition, independent technical review). The reviewer cannot be the coder or writer. The Project Director cannot commission, evaluate, or repair worker packages.

The existing project controller creates the same development mission, assignments, project-run binding, native task, financial account, and protected lifecycle reserves. It selects the package's workers instead of `team[3]`; project teams and historical projects remain unchanged. Package dependencies must precede the consumer's approved milestone, preserving cumulative execution and preventing dependency cycles. Management decisions use the existing live assignment lease and global transaction lock.

A terminal package returns to its immediate manager. That manager evaluates the original criteria against the current assignment and immutable tested/reviewed head. Rejection retains evidence and charges. A separately recorded bounded correction reuses the contract and starts from the last accepted project head. It cannot obtain another allowance by retrying. Only manager acceptance permits the existing controller to advance. Worker acceptance, director certification, superior acceptance, independent final QA, and Project Director closure remain distinct gates.

Cumulative project scope and package write scope are separate: trusted tools validate the entire baseline-to-head diff against the original project paths, and the accepted-predecessor-to-head delta against the package paths. Native dispatch compares these values with the database run binding. Recovery retains the same scope checks and existing checkpoint provenance.

All package attempts share their package resource caps in addition to the existing worker, ancestor, project, and native-account controls. Actual overruns are recorded, invalidate package acceptance, and wake the responsible manager. Unsupported final-assessment retries cannot silently fall back to the old fixed developer. Pending package responsibilities cannot be reassigned or bypassed through direct legacy RPC calls. Hierarchy changes and package commands use separate management turns to keep command ordering explicit and atomic.

## Qualification

`tests/project-organization-integration.test.mjs` installs the existing native financial stack and all three management migrations into disposable PostgreSQL, retaining snapshots of historical projects and ledgers. Its deterministic scenario:

- Commissions Architecture, Development and independent QA directors, plus a subordinate implementation manager and distinct coding workers.
- Commissions two dependent packages with different scoped paths and developer identities, neither equal to the legacy developer slot.
- Races commissioning and native authorization; rejects foreign workers, forged assignment evidence, direct assignment substitution, excess scope/resources, direct table writes and legacy helper access.
- Writes real source modules and tests in a local Git repository, uses the existing scope and native checkpoint tools, and runs Node tests and original-contract Chromium checks.
- Records actual canonical reservations and settlement with explicitly synthetic supplier usage; rejects excess package spending transactionally.
- Rejects defective arithmetic, commissions one local correction, and retains its prior attempt and financial records without executive involvement or another owner consent.
- Deletes the worker checkout and restores the exact accepted commit from a durable local Git remote. A separate PostgreSQL session verifies unchanged hierarchy, package progress and accounting.
- Tests independent QA against a seeded integration error, then the correct integrated source; records rejection and corrected evidence in the QA organization.
- Certifies workers and the implementation manager, obtains Development Director certification, and separately obtains Project Director acceptance. Architecture and QA follow the same separate certification/acceptance chain.
- Proves accepted components alone do not permit overall project completion.

The existing management PostgreSQL suite continues to qualify variable organization sizes (2 and 24 directorates), recursive depth, management tool denial, role/reorganization restrictions, original-requirement QA failure, financial closure, and historical compatibility. Focused runtime, scope, checkpoint and project-workflow regressions accompany Full CI and build. Independent review and exact candidate/check links belong in the draft PR qualification record.

## Limits and later work

- Model decisions, code generation and supplier receipts are deterministic fixtures; repository, PostgreSQL, Node and Chromium operations are real. This is not evidence of live inference autonomy or hosted delivery.
- Execution remains serialized in the existing approved cumulative milestone order and uses the supported Katie repository environment. Parallel branch integration and general repository adapters are outside this slice.
- A resource or deadline exception remains an exception; this milestone cannot invent new authority. Native protected reserves and verified model/pricing availability can prevent live admission.
- Cross-component replanning after final integrated assessment rejects an already accepted project remains fail-closed. Automatically reopening a dependency chain and requalifying all affected accepted components is a subsequent capability, not a legacy fixed-worker retry.
- Restricted publication, production deployment and original Task 4A execution remain separately authorized actions. No production migration or project execution is part of qualification.
