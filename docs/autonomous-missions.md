# Autonomous missions

Missions extend existing managed agents rather than creating another identity system. On `/agents`, select a saved team, describe an outcome, save its immutable snapshot, then explicitly start it. The existing production Vercel cron invokes `/api/internal/missions/run` every minute with the existing CRON_SECRET. Browser polling only reads state; closing the page does not stop execution. Cron timing is approximate, not a completion SLA.

Supabase stores the mission, assignments, dependencies, results, call reservations, usage and development links. One dispatcher invocation claims at most three assignments; concurrent invocations serialize admission in SQL and cannot claim the same assignment twice. Individual calls have a 90-second SDK timeout with no inference retries; one route has a 240-second hard lifetime. Six-minute leases exceed that lifetime. New scheduled invocations recover abandoned work at most once, with a new fencing token. Late workers cannot checkpoint or reserve new calls. Completed assignments remain checkpoints; a provider call interrupted before checkpointing may be billed and repeated within the retained allowance. This is not an exactly-once billing guarantee.

The coordinator uses GPT-5 Mini to propose one or two useful worker assignments, dependency ordering and a deliverable. Server validation restricts it to the saved team and supported capabilities. Final synthesis and independent review are added by the server. At most six non-planner assignments, twelve provider calls and one substantive revision are admitted. SQL also respects the smaller saved/current agent concurrency limit and active existing agent tasks. Native live web search requires the saved research permission and returns actual provider citation records. Analysis has a typed deterministic arithmetic tool: no eval, shell, arbitrary code or production access. Other workers receive only explicit mission inputs and saved mission evidence, not arbitrary actor histories or attachment stores. General-purpose sandbox execution and additional integrations are future capabilities.

The model adapter reuses the existing OpenAI credential and installed SDK, with explicit output limits and no automatic continuation. The ordinary chat provider adapters remain unchanged. Routine work uses GPT-5 Mini; review uses a separate GPT-5.4 context. Mission review reuses Katie's existing independent-assessment and answer-review instructions, source-linked assessment validator, acceptance IDs and answer-review validator. It first establishes criteria without the draft, then evaluates the explicit current candidate and supporting evidence. Missing checks, contradictory approvals and incomplete output block acceptance. A substantive revise verdict creates one revision assignment and a fresh review. A second rejection or essential missing fact blocks with retained findings. Unlike synchronous chat review, missions checkpoint between worker assignments and do not run the synchronous contract-repair loop inside one request.

Token reservations conservatively count UTF-8 input bytes plus maximum output and native search headroom. Actual provider tokens are recorded separately. Successful calls settle their reservation to measured usage and release unused headroom exactly once; uncertain calls retain their reservation. Dispatch stops when calls, estimated token reservations or mission time are exhausted. Search and provider-internal metering may differ from estimates. The initial UI estimate of approximately $1–$2 excludes hosting, assumes the configured model prices checked on 2026-10-16, and is not a guaranteed billing cap. Model rates: GPT-5 Mini $0.25/$2 input/output per million tokens; GPT-5.4 $2.50/$15. Search fees are additional. The GitHub coding workflow has its own model usage, execution-time and retry limits, outside the coordinator/worker allowance and estimate. The coding approval UI explicitly identifies these separate charges. Existing API key and provider account limits remain authoritative.

Development assignments require saved development permission and a connected repository. The exact saved assignment is shown for explicit owner approval before any GitHub write. A SQL bridge binds that approval to an existing agent task with the same UUID, input, agent version/configuration and repository. Changed agent definitions block rather than silently changing the approved work. The existing owner-authenticated dispatch claim/marker, ambiguous-acceptance reconciliation, independent GitHub tests/review/repair and trusted completion receipt are reused. Missions only accept a verified draft-ready receipt; they never merge or deploy. External workflow checks run on later cron invocations without occupying a model worker while waiting. A stopped mission does not cancel an already accepted GitHub workflow or guarantee cancellation of a provider operation already in flight.

All three new tables enable RLS, explicitly revoke inherited public/anon/authenticated/service_role grants, and grant only necessary service-role reads/inserts/updates. New functions are SECURITY INVOKER with fixed search_path and explicit service-only execution. The existing private single-owner Vercel Authentication boundary protects the UI and user-facing APIs. Do not expose the deployment publicly without adding application-level owner authorization.

Release acceptance requires real scheduled execution with the browser closed, saved worker handoffs, recovery after an abandoned worker lease, a reviewed live research/analysis deliverable and a separate approved draft-only coding mission. Fixture and SQL tests alone do not establish those outcomes. Keep the feature in pilot status until the actual mission evidence is recorded. No deployment or live acceptance is claimed by this document.
