# Standalone pricing evidence

Snapshot: `standalone-pricing-2026-10-28-v3`, reviewed 2026-10-28. Scope is first-party, global, standard, synchronous token inference in USD. The reviewed evidence is the official pages below, opened during implementation. Local SDK/provider request code was inspected first for OpenAI request shapes; the repository contained no authoritative local pricing documentation, so official OpenAI documentation supplied the financial evidence. No live paid model request was made. Version 2 added the separately verified GPT-5.4 Pro/GPT-5.5 Pro IDs and endpoint/stream restrictions; version 3 adds explicit verified Claude five-minute write rates.

`lib/standalone-accounting/pricing.ts` contains the complete immutable rate snapshot. The mutable discovered-model registry and its third-party pricing feed are deliberately excluded. Adding a model, rate or billing rule requires a new version; do not rewrite a version that has ledger rows. Every persisted estimate and approval binds the exact prepared hash and pricing version.

Estimator identity: `standalone-estimator-v5`, exported as `ESTIMATOR_VERSION`. It separately versions request counting/admissibility from financial rates. Version 2 added verified local function schemas and continuation envelopes, bounded Claude thinking/output configuration, and Gemini `responseJsonSchema`; version 3 added validated no-fee legacy OpenAI cache metadata; version 4 required frozen inline image bytes before every vision-billing rule; version 5 supports five-minute Claude cache writes with a disclosed conservative write allowance. Each actual continuation still requires its own preflight reservation and provider receipt. The full loop is never priced as a single request.

## Official evidence

OpenAI model-specific pages establish standard input, cached input and output rates: [GPT-4o](https://developers.openai.com/api/docs/models/gpt-4o), [GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini), [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1), [GPT-5](https://developers.openai.com/api/docs/models/gpt-5), [GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini), [GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4), and [o3-pro](https://developers.openai.com/api/docs/models/o3-pro). GPT-5.4 applies 2x input and 1.5x output above 272,000 input tokens, to the whole request. o3-pro has no reviewed cached rate in this snapshot. Model aliases are accepted only when listed exactly; arbitrary dated suffixes are refused.

[GPT-5.4 Pro](https://developers.openai.com/api/docs/models/gpt-5.4-pro) and [GPT-5.5 Pro](https://developers.openai.com/api/docs/models/gpt-5.5-pro) each list $30 input/$180 output per million tokens, a 1,050,000 context window and 128,000 maximum output. Exact aliases plus documented `gpt-5.4-pro-2026-03-05` and `gpt-5.5-pro-2026-04-23` snapshots are listed individually. Both require Responses. GPT-5.4 Pro applies the same 272,000-token long-context uplift as GPT-5.4; no cached rate is assumed. GPT-5.5 Pro's model page lists no long-context uplift, explicitly excludes a cache discount, and marks streaming unsupported. Its reported cached input, if any, therefore receives the full input rate. Images remain refused until their separate tokenization rules are implemented. Financial support does not authorize automatic premium helper selection.

[OpenAI images and vision](https://developers.openai.com/api/docs/guides/images-vision) supplies tile/base pricing: GPT-4o/GPT-4.1 use 85/170, GPT-4o mini 2,833/5,667, GPT-5 70/140. Low detail uses only base tokens. Auto/high uses aspect-preserving 2,048 fitting, shortest-side reduction when above 768, and 512 tiles. Other image tokenizers are refused until separately implemented. Every image requires content and dimensions obtainable from frozen inline bytes, including OpenAI low-detail and Claude fixed-maximum allowances. External image URLs are refused before those billing shortcuts because their content can change after approval; no network dereference or guessed dimensions is used.

[Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing) establishes reviewed rates for exact Sonnet/Haiku 4.5, Sonnet/Opus 4.6, and Sonnet/Opus 5.5 IDs. The snapshot uses conservative supported context limits; it does not infer prices from family names. One-hour writes and geography/fast-mode modifiers are refused. [Anthropic vision](https://platform.claude.com/docs/en/build-with-claude/vision) establishes visual-token caps of 1,568 for earlier standard-resolution models and 4,784 for 4.7+ models. An image estimate reserves the model's full documented image cap, with that assumption visible.

[Google Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing) supplies Gemini 2.5 Pro/Flash paid standard rates. Pro uses higher whole-request rates above 200,000 prompt tokens. Output rates include thinking. [Gemini image understanding](https://ai.google.dev/gemini-api/docs/image-understanding) supplies the 258-token small-image rule and approximate crop formula for larger images. Only those Gemini 2.5 vision shapes are supported; the formula's approximate nature is disclosed. Explicit positive thinking budgets are additionally allowed for in the reservation; dynamic unbounded budgets are refused.

[xAI pricing](https://docs.x.ai/developers/pricing) supplies exact Grok 4.7/4.6/4.3 rates and the inclusive 200,000-token long-context threshold. The higher rates cover every token in that request. xAI images, server tools, regional endpoints, and unlisted legacy models are refused.

## Function-only tools and finite thinking

[OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling) identifies function definitions as input-token content and documents `function_call`/`function_call_output` and chat `tool_calls`/`tool_call_id` envelopes. Only custom function definitions are allowed. Their exact canonical schemas, calls, arguments and result text contribute to the input allowance. Built-in web/file search, hosted execution and other paid server tools remain unsupported.

[Claude client tool use](https://platform.claude.com/docs/en/agents-and-tools/tool-use/overview) distinguishes locally executed functions from Anthropic server tools. [Claude pricing](https://platform.claude.com/docs/en/about-claude/pricing) charges client tools as token inference. Native custom definitions, `tool_use`, and `tool_result` content are counted. No extra local-function service fee is invented. The estimator adds a disclosed 1,024-token **heuristic** framing allowance for a nonempty function list, alongside exact canonical definition bytes. This is not a guaranteed tokenizer count.

[Claude thinking](https://platform.claude.com/docs/en/build-with-claude/thinking) and [thinking cost control](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost) establish that `max_tokens` covers thinking plus response text on each request. Output usage includes hidden thinking exactly once. The memory editor's Sonnet 5.5 `between_tools` mode is supported at high effort or below; invalid mode/effort/budget combinations fail. Legacy enabled thinking requires a finite budget below `max_tokens`. [Structured outputs](https://platform.claude.com/docs/en/build-with-claude/structured-outputs) documents `output_config.format` and additional format instructions. The exact schema is counted, plus another disclosed 1,024-token heuristic instruction allowance. Effort changes allocation inside the finite output allowance.

[Gemini function calling](https://ai.google.dev/gemini-api/docs/function-calling), [Gemini API schemas](https://ai.google.dev/api/generate-content), and [Gemini structured outputs](https://ai.google.dev/gemini-api/docs/structured-output) document function declarations, `functionCall`/`functionResponse`, thought signatures, and `responseJsonSchema`. Function argument/result objects are opaque JSON data, counted canonically; JSON keys that resemble an image or tool name inside results do not activate provider features. Known preserved reasoning and signatures are passed unchanged and counted from canonical bytes, with the hidden reconstruction uncertainty disclosed. Unknown API envelope fields fail. [xAI function calling](https://docs.x.ai/developers/tools/function-calling) documents local custom functions and separates them from paid server tools; its native chat function envelopes use the same token-only accounting approach.

## Precision, estimates and supported dimensions

[Claude prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), re-opened for the upstream five-minute-cache integration, verifies the separate write/read rates and disjoint usage counters. The immutable five-minute write rates in USD per million tokens are Sonnet 4.5/4.6 $3.75, Haiku 4.5 $1.25, Opus 4.6 $6.25, Sonnet 5.5 $2.50 and Opus 5.5 $5.00. These were checked individually against the current official table, including the lower 5.5 cache-read prices. A five-minute write replaces ordinary input billing for those tokens; it is not charged in addition to the full base-input amount.

Only `cache_control: {type: "ephemeral", ttl: "5m"}` or its documented default-five-minute form is supported, on native Claude text/image/tool content, custom tool definitions or the automatic top-level setting. Unknown fields, unsupported locations, more than four breakpoints, one-hour TTLs and other providers' use of Claude controls fail closed. The whole estimated input allowance is reserved at the reviewed five-minute write rate, including the uncached suffix/framing, with no assumed read discount. This deliberately over-allocates possible writes rather than pretending to know exact cached-prefix tokens. Exact cache markers and prefix bytes remain inside the frozen hash; a new prefix or model requires a new quote and approval.

For settlement, normalized `inputTokens` equals raw uncached `input_tokens` plus `cache_read_input_tokens` plus `cache_creation_input_tokens`. Reads and writes are disjoint subsets of that total. `priceTokenUsage` accepts verified five-minute write tokens as its fifth argument. `actualCostFromUsage` accepts `cacheWriteInputTokens` (or matching `cacheCreationInputTokens`), cached reads as `cachedInputTokens` (or matching `cacheReadInputTokens`), and requires `cacheWriteTtl: "5m"` for nonzero writes. The caller must prove TTL from the frozen all-five-minute request or a conserving `cache_creation.ephemeral_5m_input_tokens` breakdown with zero one-hour writes. Counts alone do not establish TTL. Missing/unknown/nonconserving TTL evidence and one-hour writes retain uncertain exposure instead of guessed settlement. The sum of reads and writes cannot exceed total input.

[OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), reviewed during the integration, distinguishes earlier models' no-additional-write-fee caching from GPT-5.6+/GPT-6 write rates. Version 3 allows `prompt_cache_key` only on exact reviewed OpenAI models, with nonempty well-formed keys bounded to 64 characters. The shared key schemas in [Responses compaction](https://developers.openai.com/api/reference/resources/responses/methods/compact) and [Decisions create](https://developers.openai.com/api/reference/resources/decisions/methods/create) document that limit; the stable conversation helper now emits a version prefix plus 55 digest characters (64 total), preserving actor/chat isolation.

Explicit `24h` retention is allowed only for reviewed GPT-4.1, GPT-5, GPT-5.4 and GPT-5.5 Pro (including its documented snapshot). Other reviewed earlier models allow only `in_memory`; GPT-5.5 Pro allows only `24h`. The no-fee eligibility table is explicit and independent of mutable discovery. Cache metadata stays inside the frozen serialized body/hash but contributes no prompt text tokens, assumed cache hit or admission discount. Settlement discounts only provider-reported cached input at the reviewed rate. Malformed keys/retention, other providers' use of these OpenAI fields, unknown model variants, cache breakpoints and `prompt_cache_options` fail closed. Modern 30-minute/12-hour cache writes need separately implemented financial support and are not treated as free.

Rates use integer nanoUSD per token; multiplication and aggregation use bigint, then round the aggregate upward to integer microUSD once. Public money values are decimal integer strings, never floating point dollars. Reported cache reads/writes are disjoint subsets of total input. Provider output usage must already include billable reasoning exactly once. Unsupported write-TTL/tool/audio/image-output usage must retain an uncertain reservation instead of inventing an actual charge.

A prepared request is a cloned, recursively frozen JSON payload, finite output cap, exact provider/model/endpoint, canonical serialized body, and SHA-256 hash. Default missing output caps are inserted before hashing. The dispatched body must be the frozen serialized body. Restore and reestimate verify hash integrity. Changing any payload content produces a new approval identity.

Text estimation uses one token per UTF-8 byte plus 256 request framing tokens and 32 per ordinary content object, with separate disclosed allowances for functions and structured output. This is a conservative heuristic, **not an exact tokenizer or guaranteed ceiling**. It includes the complete finite output allowance, including reasoning, and assumes no cache hit. Actual usage can exceed an estimate; settlement records that actual cost. A budget reservation controls admission and exposure, not an enforceable provider invoice cap. The result explicitly carries `isCeiling: false` and the assumptions. Unknown models, native files, audio/video, image generation, server tools, unsupported cache writes, pricing modifiers, unknown content shapes and unknown generation dimensions return `unsupported` and null monetary values. They cannot be admitted using zero or a guessed price.

Some existing provider defaults use unsupported or unverified aliases (for example `claude-4.5-sonnet` and `gemini-3.1-pro`). These are intentionally blocked; the model registry cannot provide missing financial evidence. A reviewed exact model must be selected before that request can proceed.

## Reduce cost

`reducePreparedRequest` creates a separate deterministic candidate, hash, change audit, tradeoffs and estimate. It preserves system instructions and the current user message, removes exact duplicate older messages/images, limits older conversation context (including the existing bounded episodic-history marker), caps image selection, lowers supported OpenAI tile-image detail, and may reduce output allowance. It never edits the approved original or invents rates. Missing/unsupported prices stay unsupported. The caller must persist the revised payload and require approval for its fresh hash before dispatch.

At least one context/image/detail/model lever must lower the quote; shortening output alone is insufficient. When context/images/detail do not lower the estimate, the candidate may explicitly propose a reviewed cheaper same-provider model: GPT-4o/GPT-4.1 to GPT-4o mini, exact GPT-5.4 Pro/GPT-5.5 Pro IDs to GPT-5.4, Claude Opus 4.6/5.5 to same-generation Sonnet, and Grok 4.7/4.6 to Grok 4.3. Existing official model/rate sources establish these choices; [Claude effort](https://platform.claude.com/docs/en/build-with-claude/effort) confirms the corresponding effort capabilities. Each full revised payload is reestimated against the target's reviewed context, output, vision, schema, thinking and endpoint constraints. The quality tradeoff and both model IDs appear in the audit. Opaque model-bound reasoning is never transplanted. No supported cheaper candidate means `available: false`, an unchanged request/hash/quote, an empty change audit and a visible explanation. Model changes are proposals requiring new approval, never automatic routing substitutions.

When native continuation content is present, reduction preserves the complete call/result/reasoning message chain and records that context pruning was skipped. It never rewrites schema JSON, arbitrary tool arguments/results, or opaque signed blocks. Output reduction remains available, maintaining the legacy thinking-budget constraint.
